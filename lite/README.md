# ADB Persist для Яндекс Станции Лайт 2

Держит сетевой ADB открытым даже после сброса к заводским.

Протестировано: Станция Лайт 2 (gen2), quasar 3.21,
`VERSION=3.21`, рутованная, 27.10.2026 — установка, ребут,
симуляция wipe с восстановлением, всё на железе.

## Как это работает

Загрузочная цепочка ADB на станции:

```
S99quasar → onboot.sh → activate_adb.sh check → маркеры в /data/quasar
→ yandex-debugctl adb-net → adbd на TCP 5555
```

Сброс к заводским стирает `/data` (он же `/bkupgrade/data`): аккаунт,
Wi-Fi, **оба ADB-маркера** (`activate_adb_quasmodrom`,
`activate_network_adb`) и сторож `rootkeeper.sh`. После этого `check`
не находит маркеров, тихо выходит — и adbd не стартует. Порт 5555 закрыт.

Системный раздел (`ubi0:rootfs`, `/`) сброс **не трогает**.
Патч использует это: 12 строк в `/system/vendor/quasar/onboot.sh`,
*до* вызова `check`, на каждой загрузке:

1. пересоздают оба маркера в `/data/quasar`;
2. восстанавливают `/data/quasar/rootkeeper.sh` из эталона
   `/system/vendor/quasar/rootkeeper.sh.persist` (только если его нет
   или он не executable — ручные правки не затираются).

Дальше штатная цепочка видит маркеры и поднимает adbd, а последняя
строка `onboot.sh` запускает сторожа. Файл `onboot.sh` не содержит
`set -e`, поэтому даже гипотетический сбой этих команд не роняет
загрузку — худший исход: патч молча ничего не делает.

Эталон rootkeeper — это живой `/data/quasar/rootkeeper.sh` (FORTRESS-KEEPER
v3: раз в минуту чинит маркеры и перезапускает adbd, если нет LISTEN
на :5555). Скрипт сам стянет его с устройства при установке.

## Использование

Требования на хосте: `bash`, `adb`, `patch`. Станция должна быть
доступна по ADB (по умолчанию `192.168.1.x:5555`).

```bash
# Проверить, стоит ли патч и поднят ли ADB (только чтение)
./adb-persist.sh verify [--device IP:PORT]

# Установить: бэкап → патч → проверка → remount ro
./adb-persist.sh install [--device IP:PORT] [--reboot] [--dry-run] [--force]

# Снять: вернуть стоковый onboot.sh из бэкапа, удалить эталон
./adb-persist.sh uninstall [--device IP:PORT] [--reboot] [--backup-dir DIR]
```

Установка делает бэкап (`onboot.sh`, `activate_adb.sh`, `launch.json`,
`rootkeeper.sh`) в `./backups/<timestamp>/` и сверяет установленный файл
с проверенной сборкой побайтово, прежде чем вернуть раздел в `ro`.
Флаг `--dry-run` выполняет только чтение+сборку, без записи.

## Границы и риски

- **L3 после wipe.** Патч гарантирует LISTEN :5555, но не сеть: после
  сброса станция не в домашнем Wi-Fi (S40wifi подсунет стоковый конфиг).
  Подключаться надо через setup-сеть станции — сканируй :5555 или смотри
  DHCP-таблицу роутера после онбординга.
- **OTA обновление сотрёт патч** (перезаписывает `/system`), но маркеры
  в `/data` переживут обновление — ADB, скорее всего, поднимется и на
  стоковой прошивке. Подробнее — в uninstall/backup: переприменение
  после OTA это снова одна команда `install`.
- **Полный wipe на железе не тестировался** (только удаление маркеров +
  rootkeeper с ребут-тестом — восстановление подтверждено). Настоящий
  сброс потребует заново онбордить станцию.
- При установке скрипт никогда не оставляет `/` в `rw` (trap на выход).
- Откат в любой момент: `uninstall` из `./backups/`.

## Состав

- `adb-persist.sh` — один самодостаточный скрипт (патч встроен).
- `patches/onboot-adb-persist.patch` — тот же патч отдельным файлом,
  для ревью.
- `backups/` — сюда складываются бэкапы (в git не коммитятся).
